## Unreleased (next release)

A batch of reliability fixes and new API surface, verified against the maintained `react-native-notify-kit` fork
(up to its 10.10.0):

### Features

- **android:** emit `EventType.FG_TIMEOUT` when Android 14+ times out a running foreground service; the event detail includes `startId` and `fgsType`
- **android:** `getNotificationSettings()` now reports `fullScreenIntent` permission state (full-screen intent special app access on API 34+, `USE_FULL_SCREEN_INTENT` grant on API 29–33)
- **android:** new `shouldShowRequestPermissionRationale()` API (Android 13+) to decide whether to show a custom rationale before requesting `POST_NOTIFICATIONS`
- **android:** support an explicit `pressAction: null` opt-out, which attaches no content intent — tapping the notification does nothing (no app launch, no unlock requirement, no `PRESS` event)

### Bug Fixes

- **android:** guard all `startForeground()` calls in the foreground service, so a system denial (e.g. start-intent redelivery on Android 12+) stops the service instead of crashing the app
- **android:** use stable PendingIntent identities in `ReceiverService`, so notifications dismissed/acted on across a process restart can no longer be routed to another notification's payload
- **android:** quick actions without `launchActivity`/`mainComponent` are now handled headlessly on Android 12+ instead of launching the app and requiring device unlock
- **android:** defer TurboModule resolution to first access, so importing Notifee very early (e.g. registering `onBackgroundEvent` in `index.js`) no longer throws in bridgeless mode
- **android:** buffer up to 10 events emitted while the React instance is starting (FIFO, oldest dropped) and requeue undelivered events — foreground events are no longer silently lost at startup
- **android:** re-initialize a stale React context in `HeadlessTask` instead of crashing with a null `ReactContext`
- **android:** call `requestPermission()` and `shouldShowRequestPermissionRationale()` on the main thread, fixing rejections/NPEs during screen transitions
- **android:** copy bitmaps decoded by Fresco before using them, avoiding crashes from recycled bitmaps in BigPicture/MessagingStyle notifications
- **android:** `getInitialNotification()` now uses a durable tap ledger, so a notification tap is returned at most once even across process restarts

## 9.0.0

BREAKING CHANGES!

Android 14+ requires two changes to avoid crashes or Play Store rejection

1. The USE_FULL_SCREEN_INTENT permission is not longer included by default as most apps do not need it. If you need it you must now manually add the permission to AndroidManifest.xml

2. Foreground Service Types are a strict requirement for Android 14 and require Play Store approval. You must use compileSdk 34 or higher for this release. If you need foreground service types you will need to specify the exact foreground service type permissions in your AndroidManifest.xml and you must replace the service definition in AndroidManifest.xml and you must use the new optional foregroundServiceTypes parameter in the foreground service API call

Thanks to all the contributors that proposed these fixes so that Notifee continues to work well on Android 14 - handling the platform security changes as Google makes new releases is not easy, and they _always_ change the Nofitication API surface API. Notifee would not work without the community contributions.

Note, v8.0.0 was published 2 years ago as an alpha on npmjs.com but is unused. However, the version number was consumed by that alpha publish so we have skipped to v9.

- fix(android)!: Remove USE_FULL_SCREEN_INTENT permission from package manifest for Android 14 compat (#1027)
- feat(android)!: allow adding foreground service types dynamically
- feat(android): add Android 15 FOREGROUND_SERVICE_TYPE_MEDIA_PROCESSING
- fix(types): add cancelAllNotifications optional android tag property (#1087)
- build(android): minimal set of changes for compileSdk 34
- test(lint): check native code formatting in CI
- style(lint): result of auto-formatting `yarn format:all`
- style(lint): constrain formatting globs, add formatting check run scripts
- docs(android): note apps must now manually add USE_FULL_SCREEN_INTENT if needed
